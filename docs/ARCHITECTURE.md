# Архитектура

## Слои

```
   ui/      страница прототипа: совет, карточки людей, летопись
    │
   sim/     ядро без экрана: генерация партии, решения, совет, сезоны; balance.ts — числа; rng.ts — случайность
    │
   data/    данные: оси, черты, метки, должности, стремления, предыстории, события
```

Зависимости идут только вниз: `src/ui` → `src/sim` → `src/data`. Данные не знают про логику, логика не знает про экран. Поэтому вся партия считается в Node без браузера: на этом держатся тесты (`test/`), прогон без экрана (`npm run sim`) и будущие боты (задача И3). Направление сторожит `test/rules.test.ts`.

| Папка | Назначение | Зависит от |
|---|---|---|
| `src/data/` | типы и списки: что есть в мире | ничего |
| `src/sim/` | правила: как из данных и семени получается партия | `data` |
| `src/ui/` | отрисовка и ввод; партию не считает, только зовёт функции `sim` | `sim`, `data` |
| `tools/` | сборка в один HTML, прогон без экрана, проверка длины строк | `src` |
| `test/` | тесты логики (`*.test.ts`) и проверка в браузере (`e2e/smoke.py`) | `src`, собранный `dist/` |
| `dist/` | собранный прототип `index.html`: один файл, открывается двойным щелчком; собирается командой, коммитится | — |
| `docs/design/` | замысел, решения автора, очередь задач | — |

## data: данные

- `types.ts` — типы: `Axis` (ось звезды), `Star`, `PostId`, `Faction`, `Resource`, `Trait`, `Mark`, `AspirationDef`, `BackstoryEvent`, `RosterEntry`, `GameEvent`, `EventOption`.
- `rumors.ts` — молва: по несколько строк на каждую склонность (`RUMORS_AXIS`) и ключевую черту (`RUMORS_TRAIT`).
- `core.ts` — оси `AXES` и их названия, пары трения `OPPOSED`, должности `POSTS` (у каждой сфера, две оси годности `axes` и 2–3 родные склонности `native`: их события должности задевают часто), стороны и ресурсы, ключевые черты `TRAITS` (у скрытых — `hidden` и поступок `revealedBy`), приобретаемые черты `LIFE_TRAITS` (источник `source`: привычка, должность, отношения, перелом; `lean` — тяга решений к оси; `targeted` — черта с целью), метки `MARKS`, стремления `ASPIRATIONS`, ключевые персонажи `ROSTER` (имя, возраст, авторская черта и метка, границы звезды).
- `backstory.ts` — пул событий предыстории. Событие сдвигает звезду, может родить стремление (`aspiration`) и личную связь с другим персонажем (`link`, в тексте `{other}`). Подстановки в тексте — в шапке файла.
- `events.ts` — события, которые совет решает без Сенешаля. У события одна или две сферы (`posts`), у варианта — оси (`axes`: к каким склонностям он относится), последствия для сторон и ресурсов (`effects`), пометка риска (`risky`). События с `adventurers` приходят только при открытом лабиринте.

`id` в данных — будущие ключи сохранений: существующие не менять, новое дописывать. Целостность данных (нет повторов `id`, ссылки ведут на существующее) проверяет `test/data.test.ts`.

## sim: ядро

**`rng.ts`** — класс `Rng(seed)`: `next`, `range`, `int`, `pick`, `chance`, `gauss`, `shuffle`. Единственный источник случайности: одно семя и одни действия игрока дают одну и ту же партию. Порядок обращений к генератору — часть поведения: лишний вызов `rng` меняет все партии.

**`balance.ts`** — все числа баланса. Каждое записано ручкой `k(значение, min, max, step, 'подпись')`; из одного описания собираются:
- `BALANCE` — дерево чисел, его читает логика (`BALANCE.council.sabotage`); первый уровень — раздел (`star`, `decide`, `exp`, `rel`, `council`, `loyalty`, `staff`, `know`, `traits`, `report`, `season`; `report` — цели отчёта `npm run axes`, на ход партии не влияют);
- `KNOBS` — список `{ path, def, min, max, step, label }` для ползунков спортзала;
- `getAt(path)`, `setAt(path, value)` (зажимает в диапазон и округляет до шага, меняет число прямо в `BALANCE`), `snapshotBalance()`, `restoreBalance(snap)`, `resetBalance()`.

Логика читает `BALANCE` каждый раз заново и копий не держит, поэтому ручка действует со следующего же решения.

**`axes-report.ts`** — отчёт «должность и характер» для `npm run axes` и тестов данных: `postAxisTable` (должность × склонность по событиям), `axisEffects` (плюсы и минусы склонности), `axesWarnings` (что не дотягивает до целей раздела `report`), `runStats` (прогон партий без игрока: стороны и доля решений по ведущей склонности на своей и на чужой должности).

**`sim.ts`** — партия. Состояние — объект `World`: люди (`people`), отношения пар (`rel`), кто на какой должности (`posts`), главный (`head`), сезон, накопленные изменения сторон и ресурсов, авторитет, личные дела, летопись (`log`). Человек — `Person`: звезда и стартовая звезда, черта, метка, биография, стремление, лояльность (отношение к Сенешалю), должность, стаж и опыт, наказ, счётчики решений; приобретённые черты (`gained`), молва (`rumor`), знание Сенешаля о нём (`know`: сколько было разговоров, известны ли ключевая черта, стремление, склонности, сколько раз каждую ось видели в деле), решения последних сезонов (`recent`, из них складывается привычка).

| Раздел | Функции | Что делает |
|---|---|---|
| Генерация | `newWorld(seed, labOpen)` | базовая звезда + черта и метка → прогон предыстории → нормализация звезды → стремление → отношения пар (трение осей, общая ведущая ось, личные связи) → расстановка по годности `autoAssign` |
| Перестановки | `assignCost`, `assign`, `setHead`, `talk`, `giveOrder` | действия игрока: цена в авторитете, обиды снятых и обойдённых, личные дела, наказ |
| Решения | `scoreOptions`, `decide` (внутренние) | вес варианта = звезда по осям варианта + наказ + поправки засидевшегося и черты + случайность |
| Событие | `runEvent(w, ev)` | никого на должностях — страдает порядок; один держатель — решает сам; двое — спор `council` |
| Спор | `council`, `bypass` (внутренние) | сошлись → (иначе) рассудил главный → по отношениям: ладят — договорились; терпят — компромисс или продавил; соперники — настоял и жалоба; враги — саботаж или смолчал. Хитрый, проиграв («продавил», «настоял»), может сделать по-своему в обход |
| Знание о людях | `talk`, `nextTalk`, `axisKnown`, `axisWord`, `fitWord`, `headOpinion`, `rumorCheck`, `forecast` | что игрок знает о человеке: разговоры по порядку (черты → стремление → склонности; скрытный о ключевой черте молчит, и тот же разговор идёт дальше), наблюдение (`recordChoice` считает `know.seen`), поступок выдаёт скрытую черту, ключевую или нажитую (`reveal`); годность и прогноз только по известному |
| Черты в течение жизни | `gainTrait`, `breakdown`, `lifeTraits` (внутренняя), `traitLabel` | приобретение черты с пределом, записью в летопись и биографию; раз в сезон — привычка и черты должности; должностные черты (`source: "post"`) в предел не входят, помнят свою должность (`Gained.post`) и снимаются через `traits.postTraitLag` сезонов после ухода (`dropPostTraits`); саботаж — «Злопамятный к …»; перелом — заготовка. Поправки всех черт человека складывают `mod` и `grudge` |
| Исход | `applyEffects` (внутренняя) | последствия варианта × множитель исхода × умение исполнителя; рискованное дело может провалиться |
| Сезон | `runSeason`, `upkeep` | события сезона, затем: отношения сглаживаются, стаж и опыт растут, «засиделся», лояльность по стремлениям |
| Слова и сводки | `relWord`, `loyaltyWord`, `expWord`, `isStale`, `topAxis`, `fitness`, `consistency`, `holder`, `getRel`, `postName` | то, что показывает экран и считают тесты |
| Для тестов и заготовок | `setRel`, `runEvent`, `runEvents` | задать отношения напрямую, прогнать одно событие |

Шкалы (не баланс, на них рассчитаны экран и тексты): звезда 0–10, отношения и лояльность −10…10.

## ui: экран

`main.ts` держит одну партию `w` и флаг «Взгляд дизайнера», после каждого действия перерисовывает всё: строку состояния, совет (выбор человека на должность, «сделать главным», прогноз), таблицу отношений, стороны и хозяйство, карточки людей (черты, молва, склонности словом или «?», звезда — SVG из лучей известных осей, мнение главного), летопись. Числа осей и настоящая звезда рисуются только во «Взгляде дизайнера». `index.html` — разметка с метками `/*__CSS__*/` и `/*__JS__*/`, куда сборка вставляет `style.css` и собранный код.

Экран не считает правила сам: цену перестановки берёт из `assignCost`, прогноз — из `forecast`, годность словом — из `fitWord`, что известно о человеке — из `axisKnown` и `p.know`, слова — из `relWord` и других функций ядра.

## Сборка

`tools/build.mjs`: esbuild собирает `src/ui/main.ts` со всеми зависимостями в один скрипт и вставляет его вместе со стилями в `src/ui/index.html` → `dist/index.html`. Файл самодостаточный: без сервера и сети. Проверка на GitHub пересобирает его и сверяет с закоммиченным.
