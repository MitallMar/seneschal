# Архитектура

## Слои

```
   ui/      страница прототипа: совет, карточки людей, летопись
    │
   sim/     ядро без экрана: генерация партии, решения, совет, сезоны; balance.ts — числа; rng.ts — случайность
    │
   data/    данные: оси, черты, метки, должности, стремления, предыстории, события
```

Зависимости идут только вниз: `src/ui` → `src/sim` → `src/data`. Данные не знают про логику, логика не знает про экран. Поэтому вся партия считается в Node без браузера: на этом держатся тесты (`test/`), прогон без экрана (`npm run sim`) и будущие боты (задача И3). Направление сторожит `test/rules.test.ts`.

| Папка | Назначение | Зависит от |
|---|---|---|
| `src/data/` | типы и списки: что есть в мире | ничего |
| `src/sim/` | правила: как из данных и семени получается партия | `data` |
| `src/ui/` | отрисовка и ввод; партию не считает, только зовёт функции `sim` | `sim`, `data` |
| `tools/` | сборка в один HTML, прогон без экрана, проверка длины строк | `src` |
| `test/` | тесты логики (`*.test.ts`) и проверка в браузере (`e2e/smoke.py`, разделы — `e2e/sections/`) | `src`, собранный `dist/` |
| `dist/` | собранные страницы: `index.html` — прототип совета, `natura.html` — эмулятор натуры; каждая — один файл, открывается двойным щелчком; собирается командой, коммитится | — |
| `docs/design/` | замысел, решения автора, очередь задач | — |

## data: данные

- `types.ts` — типы: `Axis` (ось звезды), `Star`, `PostId`, `Faction`, `Resource`, `Trait`, `Mark`, `AspirationDef`, `BackstoryEvent`, `RosterEntry`, `GameEvent`, `EventOption`.
- `rumors.ts` — молва: по несколько строк на каждую склонность (`RUMORS_AXIS`) и ключевую черту (`RUMORS_TRAIT`).
- `core.ts` — оси `AXES` и их названия, пары трения `OPPOSED`, должности `POSTS` (у каждой сфера, две оси годности `axes` и 2–3 родные склонности `native`: их события должности задевают часто), стороны и ресурсы, ключевые черты `TRAITS` (у скрытых — `hidden` и поступок `revealedBy`), приобретаемые черты `LIFE_TRAITS` (источник `source`: привычка, должность, отношения, перелом; `lean` — тяга решений к оси; `targeted` — черта с целью), метки `MARKS`, стремления `ASPIRATIONS`, ключевые персонажи `ROSTER` (имя, возраст, авторская черта и метка, границы звезды).
- `backstory.ts` — пул событий предыстории. Событие сдвигает звезду, может родить стремление (`aspiration`) и личную связь с другим персонажем (`link`, в тексте `{other}`). Подстановки в тексте — в шапке файла.
- `events.ts` — события, которые совет решает без Сенешаля. У события одна или две сферы (`posts`), у варианта — оси (`axes`: к каким склонностям он относится), последствия для сторон и ресурсов (`effects`), пометка риска (`risky`). События с `adventurers` приходят только при открытом лабиринте.
- `deck.ts` — колода событий акта 1 по Концепту 3: формат карточки (`DeckCard`) и две пачки — 143 карточки `DECK` (вторая знает силы из `forces.ts` и ступени нитей из `threads.ts`); слова «кому по душе» переведены в метки словаря таблицей `LIKE_WORDS`. Движка событий ещё нет: совет колоду не читает.
- `threads.ts` — каталог нитей по Концепту 3: 30 записей `THREAD_DEFS` (ступени, следы, развязки, где входит Сенешаль, связи, карточки-ступени) и карта переходов `THREAD_MAP`. `id` и имена нитей — в словаре `THREADS` (`portrait.ts`). Движка нитей ещё нет.

`id` в данных — будущие ключи сохранений: существующие не менять, новое дописывать. Целостность данных (нет повторов `id`, ссылки ведут на существующее) проверяет `test/data.test.ts`.

## sim: ядро

**`rng.ts`** — класс `Rng(seed)`: `next`, `range`, `int`, `pick`, `chance`, `gauss`, `shuffle`. Единственный источник случайности: одно семя и одни действия игрока дают одну и ту же партию. Порядок обращений к генератору — часть поведения: лишний вызов `rng` меняет все партии.

**`util.ts`** — общие помощники счёта: `clamp`, `round1`, `round2`, `round3`, `mean`. В других файлах ядра их заново не объявлять.

**`state.ts`** — состояние партии и чтение из него, без правил. Типы: `World`, `Person` и всё, что в них лежит (`Knowledge`, `Gained`, `Rumor`, `LogEntry`, `Outcome`, `Desk`, `Legacy`; хозяйство — `Economy`, `Tax`, `Ledger`, `LedgerLine`, `Elder`, `Pending`, `Zone`; авторитет — `AuthState`, `AuthLine`, `AuthKind`, `Complaint`), шкалы `STAR_MAX` и `REL_MAX`. Чтение: `getRel`, `setRel`, `holder`, `topAxis`, `postName`, `isStale`, `fitness`. Совет, хозяйство и авторитет берут состояние отсюда и ради него друг друга не импортируют.

**Циклы импортов** сторожит `test/rules.test.ts`: в `src/` их нет и быть не должно, импорты только типов не в счёт. Модули ядра импортируют друг друга напрямую. Файлов-фасадов из одних реэкспортов в ядре нет, их тоже сторожит `test/rules.test.ts`: такой файл тянет всё сразу и первым замыкает цикл.

**`balance.ts`** — все числа баланса. Каждое записано ручкой `k(значение, min, max, step, 'подпись')`; из одного описания собираются:
- `BALANCE` — дерево чисел, его читает логика (`BALANCE.council.sabotage`); первый уровень — раздел (`star`, `decide`, `exp`, `rel`, `council`, `loyalty`, `staff`, `know`, `traits`, `report`, `bots`, `natura`, `health`, `economy`, `authority`, `order`, `fall`, `world`, `season`; `report` — цели отчёта `npm run axes`, `natura` — ручки генератора натур и цели его отчёта, `health` — ручки здоровья и цели его отчёта; все три на ход партии не влияют);
- `KNOBS` — список `{ path, def, min, max, step, label }` для ползунков эмулятора;
- `getAt(path)`, `setAt(path, value)` (зажимает в диапазон и округляет до шага, меняет число прямо в `BALANCE`), `snapshotBalance()`, `restoreBalance(snap)`, `resetBalance()`.

Логика читает `BALANCE` каждый раз заново и копий не держит, поэтому ручка действует со следующего же решения.

**`natura.ts`** — генератор натур, отдельно от совета (`council/` его не зовёт; замысел — `docs/design/natura.md`). Данные — `src/data/natura.ts`: признаки `SIGNS`, натуры `NATURES` (ядро и точки кристаллизации), мешок `BAG` (врождённые черты, нажитые и перки: вектор по признакам, редкость, конфликты, повод `trigger`, замещение `replaces`; черты жизни совета лежат там же с пометкой `council`). `growPerson` растит человека к началу игры (врождённые якоря, по нажитой черте на событие предыстории — число по возрасту, дальний якорь, обязательное противоречие; веса — `candidateWeight`), `growLife` — черту или перк по поводу в игре, с замещением, `growParty` — партию со штрафом за повтор, `signsOf` и `businessStar` считают признаки и деловые склонности. **`natura-report.ts`** — метрики для `npm run natura` и тестов: `naturaMetrics`, `naturaWarnings`. С И27в: `growPerson` даёт человеку происхождение («Откуда и чей», `ORIGINS` в `src/data/origins.ts`; его черты выпадают чаще) и с долей `natura.lookShare` одну черту облика (вид `look`, вектора нет) — обе тянутся из побочного ряда `Rng.fork` и основной не сдвигают; черты с пометой `seneschal` людям не выпадают; `growSeneschal(семя, натура)` растит Сенешаля — ядро из трёх черт, часть умений и черты его мешка (`SENESCHAL`), остальное как у людей.

**`portrait.ts`** — портрет человека по Концепту 3 (И27а; замысел — `docs/design/cherty-dannye.md`, разделы 1–2; как сделано — `natura.md`, раздел 9). Данные — `src/data/portrait.ts`: словарь полей черты и правило по умолчанию `POLE_RULES` (по строке на полюс признака); типы полей — `TraitC3` в `src/data/types.ts`. `portraitOf(признаки, черты)` складывает вклад признаков и особенное черт: желания, удержки, подход, память, голос и пристрастие доклада, связи, следы, нити, дело, лихо; в `origin` — откуда каждая строка (от какого полюса или черты), в `ifs` — поправки с оговоркой, в `notes` — фразы автора. Особенное черт мешка — `src/data/traits-c3.ts` (`TRAITS_C3` под `id` черты; там же `COUNCIL_TO_BAG` — пары черт совета в мешке): `BAG` в `natura.ts` собирается из вектора и этих полей. Там же `alloysOf` — сплавы человека (`ALLOYS` в `src/data/origins.ts`): имя и особенность, когда сошлись все части. Случайности нет; совет его не зовёт.

**`health.ts`** — здоровье, отдельно от совета (замысел — `docs/design/zdorovye.md`). Данные — `src/data/health.ts`: черты здоровья `HEALTH_TRAITS` и то, как на здоровье действуют нажитые черты натуры (`NATURA_HEALTH`). `birthHealth` даёт крепость и черты при рождении (наследственные — от семьи `makeFamily`), `seasonCheck` — один сезон (старость, рана, болезнь, выбытие со службы), `liveThrough` — прожить партию или всю жизнь. **`health-report.ts`** — метрики для `npm run health`, эмулятора и тестов: `healthMetrics`, `healthWarnings`.

**`names.ts`** — генератор имени (замысел и «Как сделано» — `docs/design/imena.md`). Данные — `src/data/names.ts`: мешки основы, славянского оттенка, прозвищ и пяти народов. `makeName(rng, книга, запрос)` даёт имя по группе и полу; книга имён (`newNameBook`) следит, чтобы в одном месте и поколении не было тёзок, а когда мешок вычерпан — различает человека по мужу, по отцу или прозвищем. К партии пока не подключён: имена людей прототипа заданы в `ROSTER`.

**Эмулятор натуры** — `src/ui/natura/` (по образцу панелей совета: `main.ts` — точка входа и прогон, `app.ts` — состояние страницы и общие куски разметки, `knobs.ts` — ручки, панели `view-metrics.ts`, `view-person.ts`, `view-portrait.ts`, `view-health.ts`, `view-tables.ts`), `src/ui/natura.html`, `natura.css`; собирается в `dist/natura.html` (вторая запись в `tools/build.mjs`). Панели берут данные из `app` и зовут `app.run()`, друг друга по кругу не импортируют. Правил не считает: зовёт `rollAll`, `metricsOf`, `rollPerson`, `growParty` и рисует метрики, графики, древо одного человека и таблицы данных; ручки — `KNOBS` с путём `natura.*` и `health.*`, меняются через `setAt` и сразу пересчитывают прогон. Для автопроверок — `window.__emu` (`run`, `setKnob`, `metrics`, `health`, `people`, `portrait`).

**`economy/`** — хозяйство и подать (замысел — `docs/design/hozyaystvo.md`, как сделано — его раздел 15). Восемь модулей, зависимости в одну сторону: `zones.ts` (зоны, доверие, время года) → `ledger.ts` (строки вне плана, нижняя черта, вложения) и `doer.ts` (исполнитель, почерк, курс) → `plan.ts` (руки и план сезона) → `pay.ts` (способы платить) → `tax.ts` (урок года, плата по умолчанию, сборщица) → `season.ts` (начало партии и сезон); `view.ts` — что видит игрок. Данные — `src/data/economy.ts`: стороны `SIDES`, категории, курсы `COURSES`, старосты деревень `ELDERS`, способы платить `PAY`. Состояние — `World.eco` (`Economy`): запасы `stock`, нижние черты, курс, урок `tax`, старосты, ведомость прошлого сезона `last` и строки текущего `cur`; доверие сторон — `World.factions`. Состояние берёт из `state.ts`, совет не импортирует. Совет и сезон зовут хозяйство: `initEconomy` в `newWorld` (`council/generate.ts`), `addLine` и `addTrust` в `applyEffects` (последствия событий), `belowFloor` и `courseLean` в `scoreOptions`, `elderSaw` в `recordChoice`, `economySeason` в `upkeep`, `rollForecast` в `runSeason` (`season.ts`).

| Что | Функции | Что делает |
|---|---|---|
| Зоны | `zoneWord`, `zoneOf`, `zoneMult`, `addTrust`, `patienceWord` | слово и множитель потока по доверию стороны; терпение Герцога словом |
| Исполнитель и курс | `doer`, `courseStrength`, `courseLean`, `setCourse`, `setFloor` | как держатель должности ведёт поток; сила курса и его инерция; шатание |
| Люди | `handsNow`, `fieldHands` | руки по зонам за вычетом рекрутов; сколько в поле |
| План сезона | `planSeason` | все обычные потоки сезона на копии запасов, без случайности: по нему идут и сезон, и прогноз |
| Сезон | `economySeason`, `rollForecast` | применяет план, недодача, осенью `collect` (плательщик по умолчанию и сборщица), курс и старосты двигают доверие, зимой новый урок |
| Подать | `payOptions`, `payTax`, `autoPayTax`, `taxLeft`, `lessonOf` | способы «чем и с кого» с курсом и пределом; плата меняет запасы, доверие, руки |
| Что видит игрок | `forecastFork`, `ledgerOf`, `elderRel` | вилка прогноза по годности счетовода; строки ведомости без спрятанных |

**`world/`** — генератор мира (замысел и «Как сделано» — `docs/design/koncept-2.md`, «Генератор событий мира»). Данные — `src/data/world.ts`: метки `WORLD_TAGS`, состояния верхнего слоя `WORLD_STATES` (длительность, цена в бюджете давления, сдвиг хозяйства `shift`, отголоски `echoes` — указ или местное последствие, метки `tags` и глушимые `mutes`); у каждого события совета — свои метки `tags`. Два модуля: С И11б `apply.ts` читает партию в двух местах: `orderEdge` выбирает вид местного отголоска по краю порядка (`strict` / `free` в `EchoDef`, для дел стражи без особого вида — множители `world.guardStrict` и `world.guardFree`), `pressureEase` смягчает потери и размер указов, пока идёт кризис стороны или Сенешаль под чужой рукой. Сам генератор (`gen.ts`) по-прежнему партии не знает.
- **`gen.ts`** — сам генератор, партии не знает: состояние `WorldSim` (свой `Rng` от семени, действующие состояния, очередь отголосков, бюджет давления, погода года, вести сезона). `initWorld(seed)`, `worldStep(ws, season)` — шаг на сезон: состояния кончаются, весной тянется погода, копится бюджет, начинается новое состояние, доходят отголоски. `worldMods(ws)` — что мир делает с хозяйством (читают `economy/plan.ts` и `economy/tax.ts`), `eventWeight(ws, ev)` — вес события совета по меткам (читает `season.ts`), `worldTape(seed, n)` — лента на n сезонов без партии.
- **`apply.ts`** — мир в партии (`World.world`: `sim`, указы на столе `decrees`, прошлые `past`, урожай по годам `harvests`): `worldArrive` в начале сезона доставляет вести в летопись, применяет местные отголоски (`applyDirect` из `council/effects.ts`) и кладёт указы на стол; `payDecree`, `decreeOptions` — указ закрывается способами подати (`payOptions` и `payTax` со счётом `Bill` вместо урока); `decreesDue` в конце сезона — совет закрывает сам, остаток бьёт по терпению Герцога, двору и авторитету; `worldView` — что видит игрок.

- **`answer.ts`** — ответ совета на беду (И21; данные — `src/data/answers.ts`): `standOf(w, post)` — во сколько раз держатель ответственной должности меняет потерю и как он справился словами; `wayOf(w, kind)` — способ ответа по почерку; `softenOf(w)` и `worldModsFor(w)` — сдвиги хозяйства с ответом совета (их читают `economy/plan.ts` и `economy/tax.ts`). `gen.ts` об ответе не знает: `worldMods(ws, soft)` принимает его готовым.

Мир от совета не зависит и случайность совета не трогает: при `world.on` = 0 партия совпадает с партией без генератора.

**`order.ts` и `order-season.ts`** — порядок, шкала строгости (замысел и «Как сделано» — `docs/design/hozyaystvo.md`, раздел 8). Состояние — `World.order` (`OrderState`): отметка шкалы `level` 0–15, стража `guard`, гниль `rot`, история по сезонам. `order.ts` — чтение, без зависимостей от хозяйства: ступени `STEPS`, `stepOf`, `gradeOf`, множители ступени `orderMods(w)` (их читают `economy/plan.ts` — пошлины и цена товаров, `economy/zones.ts` — доверие деревень, `council/council.ts` — молва, `season.ts` — кражи и удачи дозора), норма `orderNorm(w)`, цена стражи `guardCost` и приказ `setGuard`. `order-season.ts` — шаг сезона `orderSeason` (его зовёт `upkeep`): толчки событий (прирост `World.resources.poryadok`), дрейф к норме, сезонные последствия ступени, гниль. События совета с пометкой `strict` приходят только со «Строгости».

**`fall/`** — кризисы сторон и падение «под чужой рукой» (замысел — `docs/design/hozyaystvo.md`, разделы 9–10, как сделано — раздел 16). Состояние — `World.fall` (`FallState`): счёт отказов по сторонам, очередь кризисов, прошедшие кризисы со сроком шрама, опала, список падений и `under` — барон, броня, свита, согнанные с должностей. `base.ts` зависит только от состояния и баланса: его читают хозяйство (`scarMult` в множителе зоны, `courtEats` в плане сезона, `baronStep` в подати и указах), совет (`staffBlock` в перестановках), авторитет (потолок) и сезон (`disgraced`). `crisis.ts` — счёт отказов (`crisisTick`), разрешение кризиса (`resolveCrisis`) и внеочередной сбор (`maybeLevy`: он лежит среди указов с пометкой `levy`). `under.ts` — причины падения (`fallReason`), падение (`fallNow`), возвращение (`comeBack`), шаг сезона (`fallSeason`: его зовёт `upkeep` после подати и указов, до ведомости авторитета) и личные дела при бароне (`sway`, `askConsent`, `stir`). Кризис — обычное событие совета из `src/data/fall.ts`: `pickDesk` кладёт его на стол, `runSeason` исполняет и передаёт исполненный вариант (`lastOpt` из `council/effects.ts`) в `resolveCrisis`. Барон берёт натуру и звезду из `natura.ts` своим генератором от семени партии. Барон: натура (словом) и склонности заданы данными в `BARONS` (`src/data/fall.ts`), по склонностям он выбирает курс; генератор натуры падение не зовёт — прототип совета от мешка черт не зависит, и данные черт в `dist/index.html` не попадают.

**`authority.ts`** — авторитет (замысел — `docs/design/avtoritet.md`, как сделано — его раздел 9). Состояние — `World.auth` (`AuthState`): строки текущего сезона `cur`, ведомость прошлого `last`, жалобы на столе `complaints`, сезоны пиров, итоги по источникам `totals`; само число — `World.authority`. Всякое изменение идёт через `addAuthority(w, v, текст, вид)`: строка в ведомость, излишек сверх `authorityCap` сгорает. `authoritySupport` считает опору сезона, `authoritySeason` (зовёт `upkeep` после хозяйства) списывает брошенные жалобы и начисляет опору; `judge` и `feast` — личные дела игрока; `addComplaint` зовёт спор в совете. Подать двигает авторитет из `economy/tax.ts` (`collect`). Рядом в совете: `World.desk` — дело сезона (`pickDesk`, `deskView`, `command`, внутренняя `runOrdered` — `season.ts`) и уговор (`persuade`, `persuadeStep` — `council/talk.ts`, поля `Person.persuade` и `agreed`).

**`bots.ts`** — боты (задание и итоги — `docs/design/boty.md`). Привычка `Habit` — набор переключателей: главный, расстановка, курс, наказ, засидевшиеся, личные дела, плата подати, нижние черты. `BOTS` — 27 ботов: у варианта есть база (`base`) и вопрос (`asks`). `playBot(seed, bot, seasons, lab)` играет партию: `setup` до первого сезона, `turn` каждый сезон, потом `runSeason`. Бот зовёт только функции экрана; своя случайность — отдельный `Rng` с семенем `семя|бот`.

Ключ `--set=путь:значение` у `npm run bots` ставит ручку на время прогона (спокойный мир: `--set=world.on:0`); блок «Мир вокруг» в отчёте — давление за акт, указы и чем закрыты, плохие по погоде годы, коридоры из `world.goal`.

**`bots-report.ts`** — `metricsOf` (34 метрики партии, список `METRICS`), `botStats` (средние и разброс по семенам), `pairStats` (разница «партия к партии», вердикт по порогам `bots.weak` и `bots.strong`; метрики `own` бота в вердикт не идут), `botsReport` (все боты выбранных уровней, пары, заготовки против обычной партии). Исход каждого события совет пишет в запись летописи (`LogEntry.outcome`) — по нему считаются споры.

**`bots-seek.ts`** — бот-искатель (задание и находки — `docs/design/boty.md`, раздел 23). Стратегия — та же `Habit`; `SPACE` — варианты по каждой привычке, `enumerated` — «Хозяин» с одной и двумя изменёнными привычками, `randoms` — случайные стратегии своим генератором, `seek` — отбор на `bots.seekScreen` партиях, сборка по шагам на `bots.seekClimb`, подтверждение на `bots.seekConfirm` партиях со следующих семян (`botStats(…, from)`), находки «лучше» по целям `GOALS` и «необычно» по метрикам `ODD`. Печатает `tools/seek.ts` (`npm run seek`). В партию искатель ничего не пишет и ход партий не меняет.

**`probe.ts`** — зонд: счётчики для отчётов, которых нет в состоянии партии (наказ сработал или нет, меры автоплаты после жатвы, недоданное и ушедшее доверие). Их пишут `decide` (`council/decide.ts`) и `collect` (`economy/tax.ts`) и `economySeason` (`economy/season.ts`); `playBot` сбрасывает зонд перед партией и забирает после. В партию зонд не пишет и случайность не тянет: отпечаток партий от него не зависит. Уровень 4 в `BOTS` — перепроверки (`boty.md`, раздел 11); `outcomeStats` в `bots-report.ts` считает последствия дел по исходам.

**Сила потока и почерк** (`economy/doer.ts`, данные — `src/data/handwriting.ts`; замысел — `docs/design/lyudi-i-ishody.md`). `doer(w, post)` возвращает силу потока: `mastery` (годность → ×0,8…×1,2) × опыт × настрой, словами — `note` (идёт в ведомость) и `hand` (почерк; в ведомость не идёт, чтобы не выдать склонности). `handsOf(p, post)` — почерки человека: ведущая сильная склонность и оттенок второй; `levers(w)` складывает рычаги всех пятерых (`LEVERS`), `planSeason` умножает на них потоки, `economySeason` двигает ими доверие сторон, порядок и терпение Герцога. Вложения: `invest` кладёт отдачу в `eco.pending`, `settle` в начале сезона выдаёт её строкой в ведомость; `takeHands` занимает руки людей замка на сезон. В совете: `applyEffects` (`council/effects.ts`) знает род варианта (`careful`, `risky`), `council` (`council/council.ts`) — шкалу исходов и слаженность совета (`councilSteady`, `councilFeud` из `authority.ts`).

**`economy-report.ts`** — метрики для `npm run economy` и тестов: `economyMetrics` (партии играют боты `PAYERS`), `freeYear` (год без событий, все стороны в одной зоне), `economyNotes` (замечания по целям `economy.goal`).

**`axes-report.ts`** — отчёт «должность и характер» для `npm run axes` и тестов данных: `postAxisTable` (должность × склонность по событиям), `axisEffects` (плюсы и минусы склонности), `axesWarnings` (что не дотягивает до целей раздела `report`), `runStats` (прогон партий без игрока: стороны и доля решений по ведущей склонности на своей и на чужой должности).

**`council/` и `season.ts`** — партия: совет и сезон. Модули совета, зависимости в одну сторону: `people.ts` (поправки черт, отношения пар, подстановки в текстах) → `know.ts` (знание о людях и слова для экрана), `decide.ts` (вес варианта и выбор) → `traits.ts` (черты в течение жизни), `effects.ts` (последствия события — единственный вход в запасы, доверие и порядок), `talk.ts` (разговор и уговор) → `council.ts` (событие, спор, исходы) → `season.ts` (дело на столе и приказ, события сезона, `upkeep`) → `generate.ts` (новая партия) → `staff.ts` (перестановки, наказ). В таблице ниже раздел назван так же, как тема модуля. Веса вариантов последнего события (`trace`) копит `decide.ts`, исход и «в обход» (`outcome`, `bypassed`) — `council.ts`: это переменные модулей, в партию они попадают только через запись летописи.

Состояние (типы лежат в `state.ts`) — объект `World`: люди (`people`), отношения пар (`rel`), кто на какой должности (`posts`), главный (`head`), сезон, накопленные изменения сторон и ресурсов, авторитет, личные дела, летопись (`log`). Человек — `Person`: звезда и стартовая звезда, черта, метка, биография, стремление, лояльность (отношение к Сенешалю), должность, стаж и опыт, наказ, счётчики решений; приобретённые черты (`gained`), молва (`rumor`), знание Сенешаля о нём (`know`: сколько было разговоров, известны ли ключевая черта, стремление, склонности, сколько раз каждую ось видели в деле), решения последних сезонов (`recent`, из них складывается привычка).

| Раздел | Функции | Что делает |
|---|---|---|
| Генерация | `newWorld(seed, labOpen)` | базовая звезда + черта и метка → прогон предыстории → нормализация звезды → стремление → отношения пар (трение осей, общая ведущая ось, личные связи) → расстановка по годности `autoAssign` → наследство прежних баронов `inherit`: одна-две должности не по годности, запись в `w.legacy` |
| Перестановки | `assignCost`, `assign`, `setHead`, `talk`, `giveOrder` | действия игрока: цена в авторитете, обиды снятых и обойдённых, личные дела, наказ |
| Решения | `scoreOptions`, `decide` (внутренние) | вес варианта = звезда по осям варианта + наказ + поправки засидевшегося и черты + случайность |
| Событие | `runEvent(w, ev)` | никого на должностях — страдает порядок; один держатель — решает сам; двое — спор `council` |
| Спор | `council`, `bypass` (внутренние) | сошлись → (иначе) рассудил главный → по отношениям: ладят — договорились; терпят — компромисс или продавил; соперники — настоял и жалоба; враги — саботаж или смолчал. Хитрый, проиграв («продавил», «настоял»), может сделать по-своему в обход |
| Знание о людях | `talk`, `nextTalk`, `axisKnown`, `axisWord`, `fitWord`, `headOpinion`, `rumorCheck`, `forecast` | что игрок знает о человеке: разговоры по порядку (черты → стремление → склонности; скрытный о ключевой черте молчит, и тот же разговор идёт дальше), наблюдение (`recordChoice` считает `know.seen`), поступок выдаёт скрытую черту, ключевую или нажитую (`reveal`); годность и прогноз только по известному |
| Черты в течение жизни | `gainTrait`, `breakdown`, `lifeTraits` (внутренняя), `traitLabel` | приобретение черты с пределом, записью в летопись и биографию; раз в сезон — привычка и черты должности; должностные черты (`source: "post"`) в предел не входят, помнят свою должность (`Gained.post`) и снимаются через `traits.postTraitLag` сезонов после ухода (`dropPostTraits`); саботаж — «Злопамятный к …»; перелом — заготовка. Поправки всех черт человека складывают `mod` и `grudge` |
| Исход | `applyEffects` (внутренняя) | последствия варианта × множитель исхода × умение исполнителя; рискованное дело может провалиться |
| Сезон | `runSeason`, `upkeep` | события сезона, затем: отношения сглаживаются, стаж и опыт растут, «засиделся», лояльность по стремлениям |
| Слова и сводки | `relWord`, `loyaltyWord`, `expWord`, `isStale`, `topAxis`, `fitness`, `consistency`, `holder`, `getRel`, `postName` | то, что показывает экран и считают тесты |
| Для тестов и заготовок | `setRel`, `runEvent`, `runEvents` | задать отношения напрямую, прогнать одно событие |

Шкалы (не баланс, на них рассчитаны экран и тексты): звезда 0–10, отношения и лояльность −10…10.

## ui: экран

**Эмулятор совета** — та же страница `dist/index.html`. Вкладки «Совет и люди», «Хозяйство и подать» и «Мир» (`setTab`), справа всегда сводка (`renderYear`) и летопись. Панель ручек (`renderKnobs`) строится из `KNOBS` по первому уровню пути (подписи разделов — `SECTION_NAMES`; натура и здоровье — в эмуляторе натуры); два набора значений `sets` — «было» и «стало» (`switchSet`), правка ручки меняет включённый набор; `dumpKnobs` выгружает изменённое текстом. Заготовки ситуаций — `src/sim/presets.ts`: `PRESETS` и `newPreset(seed, id, lab)` (партия по семени, поправленная заготовкой). Горячие клавиши — один обработчик `keydown` по `event.code`. `syncUrl` держит в адресе `seed`, `preset`, `lab`, `designer`, `tab`, `knobs`. Веса вариантов решения копятся в `decide` (`council/decide.ts`) и лежат в записи летописи `LogEntry.weights`; экран показывает их только во «Взгляде дизайнера». `window.__emu` (`restart`, `season`, `setKnob`, `snapshot`) — для автопроверок.

Экран лежит в `src/ui/council/`. `app.ts` — состояние экрана одним объектом `app` (партия `app.w`, «Взгляд дизайнера» `app.designer`, вкладка `app.tab`, перерисовка `app.render()`), адрес страницы (`syncUrl`) и мелкие слова и числа для показа. Панели: `view-council.ts`, `view-people.ts`, `star.ts`, `view-desk.ts`, `view-economy.ts`, `view-log.ts`, `view-world.ts` (строка «что в мире», указы на столе, вкладка «Мир» с лентой по слоям), `view-order.ts` (шкала порядка и приказ страже); ручки эмулятора — `emu.ts`. `main.ts` — точка входа: `start`, `seasons`, `render`, вкладки, кнопки, горячие клавиши, параметры адреса, `window.__emu`; он вписывает `render` в `app.render`, поэтому панели зовут перерисовку через `app` и точку входа не импортируют (иначе цикл). `src/ui/dom.ts` — `$` и `esc`, общие с эмулятором натуры.

`main.ts` держит одну партию (`app.w`) и флаг «Взгляд дизайнера», после каждого действия перерисовывает всё: строку состояния, совет (выбор человека на должность, «сделать главным», прогноз), таблицу отношений, стороны и хозяйство, карточки людей (черты, молва, склонности словом или «?», звезда — SVG из лучей известных осей, мнение главного), летопись. Числа осей и настоящая звезда рисуются только во «Взгляде дизайнера». `index.html` — разметка с метками `/*__CSS__*/` и `/*__JS__*/`, куда сборка вставляет `style.css` и собранный код.

Экран не считает правила сам: цену перестановки берёт из `assignCost`, прогноз — из `forecast`, годность словом — из `fitWord`, что известно о человеке — из `axisKnown` и `p.know`, слова — из `relWord` и других функций ядра.
