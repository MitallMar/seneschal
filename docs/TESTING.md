# Как проверять изменения

## Каждый раз

```
npm run check
```

Проверка типов (`tsc`), линтер и длина строк, тесты логики, сборка `dist/index.html`. Занимает несколько секунд, браузер не нужен. По частям: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.

**Как читать вывод.** Каждая строка с `✔` — пройденная проверка, с `✖` — непройденная: под ней написано, что ожидалось и что получилось. В конце итог: `pass 79`, `fail 0`. Один файл: `node --import tsx --test test/sim.test.ts`.

**Отпечаток партий** (`test/parties.snapshot.json`). Сторожит правило «те же семена — те же партии». Правка экрана, сборки или порядка кода менять его не должна: если `test/parties.test.ts` упал после такой правки, поведение изменилось нечаянно (частая причина — лишнее или пропущенное обращение к `rng`). Правка, которая меняет ход партий намеренно (число в `balance.ts`, правило совета, данные событий), записывает новый отпечаток командой `UPDATE_SNAPSHOT=1 npm test` и говорит об этом в сообщении коммита.

**Длина строк кода** (`tools/long-lines.mjs`, входит в `npm run lint`). Считается длина строки без русского текста: тексты событий, биографии, подписи ручек и комментарии пишутся одной длинной строкой, это в счёт не идёт. Строка, в которой больше 250 знаков кода или разметки, проверку не проходит: её нужно разбить. Новые строки лучше держать до 180. `node tools/long-lines.mjs --top 20` показывает самые плотные строки.

**Линтер** (`eslint.config.js`): ESLint с разбором TypeScript; предупреждение тоже валит проверку. В `src/sim` и `src/data` имена DOM и `Math.random` — ошибка.

**Отчёт о здоровье** (справка): `npm run health` печатает, сколько людей за партию слегает, выбывает и умирает, срок жизни, частоту черт здоровья и предупреждения; `--save` и `--diff` — как у отчёта натуры, снимок `tools/health.snapshot.json`. После правки черт здоровья или ручек раздела `health`: `--diff --save`, числа в `docs/design/zdorovye.md` обновить.

**Отчёт по ботам** (справка): `npm run bots` играет сто семян каждым ботом и печатает первые строки (решает ли, на кого оставил; что даёт игра руками), таблицы по уровням и пары с вердиктом. `npm run balance -- --diff` — только первые строки и что изменилось против снимка `tools/balance.snapshot.json`; `--save` записывает снимок, он коммитится вместе с правкой `balance.ts` или правил.

**Отчёт о хозяйстве** (справка): `npm run economy` печатает по четырём плательщикам, в какой доле партий урок закрыт в срок, чем и с кого платили, сколько сезонов с недодачей, терпение Герцога и зоны сторон к концу, и таблицу «год без событий» по зонам; `--save` и `--diff` — снимок `tools/economy.snapshot.json`, коммитится вместе с правкой ручек `economy`.

**Отчёт генератора натур** (справка): `npm run natura -- --rolls=1000` печатает метрики раздела 6 `docs/design/natura.md`, предупреждения и пять примеров людей; `--save` записывает снимок метрик в `tools/natura.snapshot.json`, `--diff` сравнивает с ним. После правки мешка или ручек раздела `natura`: `--diff --save`, снимок коммитится, числа в разделе 9 `natura.md` обновляются.

**Отчёт «должность и характер»** (справка): `npm run axes` печатает таблицу «должность × склонность» по событиям, плюсы и минусы склонностей, итог прогона 20 семян × 20 сезонов и замечания, если цель раздела `report` не выполнена. После правки `src/data/events.ts` перезапусти и обнови числа в `docs/design/dolzhnost-i-harakter.md`.

**Прогон без экрана** (не проверка, а справка): `npm run sim -- замок 12` печатает сводку по партии с семенем «замок» за 12 сезонов — у кого какая звезда, сколько решений совпало с ведущей осью, отношения в совете; с `--log` — всю летопись.

## Проверка в браузере

```
npm run build && npm run e2e
```

`test/e2e/smoke.py` (Python + Playwright) открывает собранный `dist/index.html` в Chrome и играет. Сам `smoke.py` — только запуск; разделы лежат по файлу на раздел в `test/e2e/sections/` (`base.py`, `staff.py`, …), общее для них — `test/e2e/common.py` (`ok`, `open_game`, что читать со страницы). Проверка разбита на независимые разделы: у каждого своя вкладка и своя партия, от соседей он не зависит. В конце каждого раздела — на странице и в консоли браузера не должно быть ошибок.

| Команда | Что делает |
|---|---|
| `npm run e2e` | все разделы, по три одновременно (несколько секунд) |
| `npm run e2e -- staff` | один раздел по имени (или началу имени) |
| `npm run e2e -- staff talk` | несколько разделов |
| `npm run e2e -- --list` | список разделов с описаниями |
| `npm run e2e -- --jobs 1` | все разделы по одному, как на GitHub |

| Раздел | Что проверяет |
|---|---|
| `base` | запуск: совет из пяти, десять карточек, склонности закрыты («?»), о каждом молва или черта, строка-подсказка; сезон и «+5 сезонов», летопись; новая партия с тем же семенем повторяет летопись слово в слово, с другим — нет |
| `staff` | перестановки: цена в списке должности и списание авторитета, прежний держатель без места, пустая должность, назначение на пустую бесплатно, «сделать главным», желанная должность |
| `talk` | личные дела: три разговора открывают по порядку черту, стремление и склонности словами, три дела за сезон, наказ стоит авторитета один раз, новый сезон возвращает дела |
| `designer` | «Взгляд дизайнера»: числа лояльности, отношений, годности и осей, стремления и черты всех (скрытые помечены), верна ли молва, настоящая и стартовая звезда; партию не меняет; выключается обратно |
| `know` | знание о людях: годность словом в списках, мнение главного, скрытую черту разговор не открывает, отметки «видели» и ось словом после наблюдения, звезда только из известного, нажитые черты на карточках и в биографии |
| `economy` | хозяйство и подать: четыре полосы категорий с прогнозом вилкой и нижней чертой, шесть сторон и двое старост, «Тиун» в совете, дорожка сезонов с уроком, плата подати (серебро, рекруты, зерно сверх оброка) и её последствия, курс, нижняя черта, ведомость прошлого сезона по наведению, жатва и сборщица осенью, новый урок зимой, числа во «Взгляде дизайнера», пять лет партии |
| `authority` | авторитет: число и потолок, опора и из чего она, дело сезона с советом и приказ, праздник (авторитет за еду, второй раз вдвое меньше), уговор и снятие без потери, ведомость прошлого сезона, суд по жалобе, тридцать сезонов не выше потолка; наказы до нуля: надбавка ниже 5, без авторитета наказ и снятие закрыты, уговор доступен |
| `emu` | эмулятор: вкладки и сводка, клавиши (пробел, F, R, D, Tab, 1, 2, P; в поле ввода не срабатывают), ручки по разделам, ручка сразу меняет прогноз и партию, «было / стало», сброс, выгрузка, заготовки, `window.__emu`, параметры адреса, веса вариантов во «Взгляде дизайнера» |
| `natura` | эмулятор натуры (`dist/natura.html`): прогон и карточки метрик без предупреждений, графики и тепловые карты на все натуры и черты, таблицы наполнения, человек с древом и реролл, фильтр мешка, ручка действует сразу и подсвечивается, «Выгрузить изменённые», «Сброс», ссылка с прототипа совета; раздел «Здоровье»: карточки, графики, лента двадцати лет человека, семьи в партии, таблица черт, ручка здоровья меняет числа |
| `lab` | лабиринт: приключенцы приходят только при галочке; долгая партия в 80 сезонов, летопись держит последние 250 записей |
| `world` | мир вокруг: строка «что в мире», вкладка «Мир» по адресу, лента на 50 сезонов по трём слоям и её независимость от игры, указ на столе с ценой способов и его закрытие серебром, «Взгляд дизайнера» (бюджет давления), спокойный мир и множитель акта ручкой |
| `order` | порядок: шкала из шестнадцати отметок двумя цветами, ступень и норма, приказ страже затянуть (каждый шаг дороже) и отпустить, шкала доходит до «Строгости», «Взгляд дизайнера», ручки |

**Какой раздел запускать.** После правки достаточно разделов, которые она задевает: правил перестановки — `staff`, разговор и наказ — `talk`, знание о людях и черты — `know` и `talk`, вид карточек и «Взгляд дизайнера» — `designer` и `base`. Правка общего кода (`src/sim/state.ts`, `src/sim/council/`, `src/sim/season.ts`, `balance.ts`, `src/ui/council/main.ts` и `app.ts`, `src/ui/dom.ts`, `index.html`, `style.css`, `tools/build.mjs`) — полный прогон. Полный прогон в любом случае делает GitHub на каждый pull request.

**Как читать результат.** Последняя строка — итог: «все 87 проверок в браузере прошли» или «2 из 87 НЕ ПРОШЛО». Непройденная проверка печатается с именем раздела и тем, что увидел сценарий: `FAIL [staff] перестановка списала авторитет по цене из списка …`. Если раздел упал с ошибкой в самой проверке, он считается непройденным (строка «раздел дошёл до конца» с номером строки в `smoke.py`), остальные идут дальше. Все проверки поимённо: `VERBOSE=1 npm run e2e`.

**Снимки экранов** кладутся в `test/e2e/shots/` (в git не идут): `fall-crisis`, `fall-under`, `order`, `world`, `world-decree`, `start`, `seasons`, `staff`, `talk`, `designer`, `know`, `know-designer`, `economy`, `economy-ledger`, `authority`, `emu`, `emu-knobs`, `long`, `natura`, `natura-bad`. Автотесты не видят вёрстку: после правки `src/ui/` или `style.css` посмотри снимки глазами.

**Новая проверка.** К теме существующего раздела — дописать в него. Новая тема — новый раздел: функция с `@section(имя, описание)`, вкладку открывает сама через `open_game(br, errs)`; на состояние других разделов не рассчитывать.

**Браузер.** Берётся Chrome по пути из переменной `CHROME` (по умолчанию `/usr/bin/google-chrome`). Если такого файла нет — Chromium, поставленный командой `python3 -m playwright install chromium`. Нужен пакет Python: `pip install playwright`.

## Проверка на GitHub (CI)

Файл `.github/workflows/ci.yml`. Запускается на каждый push в `main` и на каждый pull request (то есть на каждый push в ветку, у которой открыт PR), занимает одну-две минуты.

| Шаг | Что ловит |
|---|---|
| `npm ci`, `npm run check` | типы, линтер, длина строк, все тесты логики, сборка |
| `dist/` соответствует исходникам | сборку забыли пересобрать или собрали из других исходников: автор играл бы не в то, что в коде |
| Браузер для проверки | не проверка: печатает версию Chrome на машине GitHub, а если его нет — ставит Chromium |
| `npm run e2e` | поломки прототипа в настоящем браузере: все разделы, по одному |
| Снимки экранов | не проверка: снимки из `test/e2e/shots/` прикладываются к прогону (на странице прогона внизу, раздел Artifacts, файл `snimki-ekranov`, хранится 14 дней) Не выгрузились (кончилась квота хранилища артефактов) — прогон остаётся зелёным |

Красный прогон = в репозитории сломанный прототип, чинить до следующей задачи.

**Как читать результат из сессии Claude Code.** Итог: `gh api repos/MitallMar/seneschal/commits/SHA/check-runs` — у проверки поля `status` (`queued`, `in_progress`, `completed`) и `conclusion` (`success`, `failure`). Логи шагов через прокси сессии не читаются (403). Причину красной проверки ищи так: аннотации `gh api repos/MitallMar/seneschal/check-runs/ID/annotations` (непройденная проверка в браузере и несобранный `dist/` пишут туда строку с объяснением); затем воспроизведи локально в чистой копии теми же командами, что в `ci.yml`: `npm ci`, `npm run check`, `git status --porcelain -- dist`, `GITHUB_ACTIONS=1 npm run e2e`.

**Публикация на GitHub Pages** (задача `deploy`): после зелёной проверки в `main` выкладывает `dist/index.html` как страницу. По умолчанию выключена. Включает автор: Settings → Pages → Source: GitHub Actions, затем Settings → Secrets and variables → Actions → Variables → новая переменная `PAGES_DEPLOY` со значением `on`. Страница публичная: прототип увидит любой, у кого есть ссылка.

## Что запускать после какой правки

| Правка | Запускать |
|---|---|
| Любая | `npm run check` |
| Число в `src/sim/balance.ts` | `npm run check`; отпечаток партий изменится — `UPDATE_SNAPSHOT=1 npm test`, затем `npm run e2e` |
| Данные в `src/data/` | `npm run check` (тест данных; новое событие меняет отпечаток партий), `npm run e2e -- base lab` |
| Правила совета и сезона: `src/sim/council/`, `src/sim/season.ts` | `npm run check`, полный `npm run e2e`, глазами — `npm run sim -- замок 12 --log` |
| Хозяйство: `src/sim/economy/`, `src/data/economy.ts`, ручки `economy` | `npm run check`, `npm run economy -- --diff --save`, `npm run e2e -- economy base` |
| Мир: `src/sim/world/`, `src/data/world.ts`, ручки `world` | `npm run check`, `npm run balance -- --diff --save`, `npm run economy -- --diff --save`, `npm run e2e -- world base` |
| Экран `src/ui/`, `style.css`, `index.html` | `npm run check`, разделы по теме или полный `npm run e2e`, посмотреть снимки |
| `tools/build.mjs`, `package.json`, `.github/workflows/ci.yml` | `npm run check`, полный `npm run e2e`; итог покажет проверка GitHub на pull request |
| Только документы в `docs/` | ничего |

## Как понять, что тест что-то ловит

После новой проверки на минуту сломай то, что она охраняет (поменяй множитель саботажа на единицу, убери списание авторитета), и убедись, что тест упал.
