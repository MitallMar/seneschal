# Очередь задач

Сюда записываются задачи для Claude Code: решение принято в чате проекта на claude.ai, текст задачи лежит здесь. Задачи делаются по одной, сверху вниз.

**Как дать задачу Claude Code:** «Сделай следующую задачу из docs/design/backlog.md» (или «задачу И2»).

**Правило для Claude Code:** когда задача сделана, тем же коммитом поставь у неё `[x]`, дату (по Москве) и одну строку итога, и перенеси её в «Сделано». Если сделать не получилось или нужно решение автора, не отмечай её, а допиши под ней «Вопрос автору: …».

**Образец правил и устройства:** игра автора «Тетрадь по схемотехнике» (репозиторий `MitallMar/tetrad-po-skhemotekhnike`): `CLAUDE.md`, `docs/ARCHITECTURE.md`, `docs/TESTING.md`, `.github/workflows/ci.yml`, `src/shelter/balance.js` (ручки), `src/ui/shelter/gym.js` (спортзал), `src/shelter/bots.js` и `tools/shelter-*.mjs` (боты и скрипты), `test/shelter/rules.test.js` (тест правил слоёв), `test/e2e/smoke.py` (проверка в браузере). Движок там другой (JS, расчёт схем), переносятся принципы, а не код. Отличие: здесь TypeScript.

## Открытые

### По порядку

- [ ] **И1. Основа проекта по правилам «Тетради»: ручки баланса, тесты, CI, памятка**
  1. **Ручки баланса.** `src/sim/config.ts` заменить на `src/sim/balance.ts` по образцу `balance.js` «Тетради»: каждое число — ручка `k(значение, min, max, step, 'подпись по-русски')`; из одного описания собираются `BALANCE` (дерево чисел, его читает логика) и `KNOBS` (список `{ path, def, min, max, step, label }`); функции `getAt`, `setAt` (зажимает в диапазон и округляет до шага), `snapshotBalance`, `restoreBalance`, `resetBalance`. Логика читает `BALANCE` каждый раз заново, без копий, чтобы ручка действовала сразу.
  2. **Слои и тест правил.** Направление зависимостей: `src/ui` → `src/sim` → `src/data`. `src/sim` и `src/data` не трогают DOM и не зовут `Math.random` (только `rng.ts`). Тест (по образцу `test/shelter/rules.test.js`) читает импорты и падает при нарушении; он же проверяет, что у каждого числа в `balance.ts` есть ручка и значение по умолчанию в диапазоне.
  3. **Тесты логики** (`node --test` через `tsx` или аналог): одно семя — одна и та же партия (детерминизм); генерация даёт 10 персонажей с биографией и стремлением; звезда в пределах 0–10; перестановки списывают авторитет по правилам (пустая и желанная должность бесплатно, снять против воли — дороже со стажем); исходы спора совета зависят от отношений (на подобранных отношениях проверить «сошлись», «рассудил главный», «саботаж»); прогон 20 сезонов без ошибок на нескольких семенах.
  4. **Проверка в браузере** по образцу `test/e2e/smoke.py` (Python + Playwright, Chrome): открыть собранный `dist/index.html`, прогнать сезоны, переставить человека, поговорить, включить «Взгляд дизайнера»; нет ошибок в консоли; снимки экрана в `test/e2e/shots/`. Разделы и `--list`, как в «Тетради».
  5. **Команды** в `package.json`: `check` (типы `tsc`, линтер, тесты, сборка), `test`, `lint`, `build`, `e2e`, `sim`. Линтер — ESLint с поддержкой TypeScript и проверка длинных строк, как `tools/long-lines.mjs`.
  6. **CI** `.github/workflows/ci.yml` по образцу «Тетради»: на каждый push в `main` и pull request — `npm ci`, `npm run check`, проверка, что `dist/` собран из этих исходников, `npm run e2e`, снимки экранов артефактом. Публикацию на GitHub Pages оставить выключенной переменной `PAGES_DEPLOY`, как там.
  7. **Памятка `CLAUDE.md`** по образцу «Тетради»: что за проект; замысел в `docs/design/` (главная версия, правило старшинства); очередь задач; таблица «задача → какие файлы читать и править»; правила (ниже). Плюс `docs/ARCHITECTURE.md` (слои, папки, ядро, данные) и `docs/TESTING.md` (что запускать после какой правки, CI, как читать результат). README обновить: «Что уже есть» и «Что будет дальше».
  8. **Правила для `CLAUDE.md`** (перенести из «Тетради», адаптировать):
     - после любой правки `npm run check`; браузерные разделы — те, что правка задевает; все — после общего кода;
     - законченная задача всегда попадает в `main`: ветка → pull request → дождаться зелёной проверки GitHub → слить самому, не спрашивая автора; красную проверку сначала починить. Документы (`docs/design/`, `backlog.md`) чат проекта коммитит прямо в `main`;
     - сообщение коммита по-русски: что изменилось для игрока;
     - `src/sim` и `src/data` не трогают DOM; числа только в `balance.ts`; случайность только через `rng.ts` с семенем;
     - `dist/` только собирается командой и коммитится вместе с исходниками: по нему автор играет;
     - не менять `id` существующих персонажей, событий, черт, меток и должностей без причины: позже под ними будут сохранения;
     - строка кода до 180 знаков (предел 250), русский текст и комментарии — одной строкой любой длины;
     - время и даты — московские (UTC+3);
     - замечания по доступу к GitHub из сессий Claude Code: GraphQL недоступен (`gh pr create` не работает) — pull request создавать и сливать через REST: `gh api -X POST repos/MitallMar/seneschal/pulls ...`, `gh api -X PUT repos/MitallMar/seneschal/pulls/N/merge -f merge_method=squash`; итог проверки — `gh api repos/MitallMar/seneschal/commits/SHA/check-runs` (поля `status`, `conclusion`) и аннотации `.../check-runs/ID/annotations`; логи Actions через этот прокси не читаются — причину красной проверки воспроизводить локально теми же командами, что в `ci.yml`.
  9. Поведение прототипа не меняется: те же семена дают те же партии, что сейчас (кроме случаев, где правка ручек этого требует — тогда записать в итог задачи).

- [ ] **И2. Спортзал совета**
  Прототип становится спортзалом по образцу `gym.js` «Тетради»: панель ручек из `KNOBS`, сгруппированная по разделам, изменённые подсвечены; «Сброс»; «Выгрузить» (P) — текст изменённых значений для копирования в чат; «было / стало» (1 / 2) — два набора значений, переключение на ходу. Параметры адреса: `?seed=…&preset=…&lab=1&designer=1`. Заготовки ситуаций (`preset`): враги в совете, засидевшийся писарь, все новички, пустая должность, главный без признания. Горячие клавиши по `event.code`: Space — сезон, F — +5 сезонов, R — заново, D — взгляд дизайнера, Tab — ручки. В «Взгляде дизайнера» у каждого решения в летописи — веса вариантов (из чего сложился выбор). `window.__gym` для автопроверок (restart, season, setKnob, snapshot). Проверка в браузере — раздел `gym`.

- [ ] **И3. Боты совета и скрипты баланса**
  По образцу `bots.js` и `tools/shelter-*.mjs`. Бот — привычки игрока, действует только функциями, которыми пользуется экран: «ничего не трогает», «ставит по годности», «ставит по стремлениям», «переставляет засидевшихся», «говорит со всеми», «даёт наказы», «случайный». `npm run bots -- --seeds=20`: таблица по ботам — доля решений по ведущей оси у членов совета, споры и их исходы, саботажи и жалобы, лояльность, авторитет, стороны. Пары ботов, различающихся одним решением: если пара нигде не расходится — предупреждение «решение пустое». Разброс по семенам: где исход решает удача. Снимок баланса `npm run balance -- --save` / `--diff` в `tools/balance.snapshot.json`, коммитится вместе с правкой `balance.ts`.

### Ждут решения автора

- [ ] **Д1. Должность и характер.** Прогоны прототипа: у части членов совета решения совпадают с ведущей склонностью в 7–45% случаев — события их должности почти не задевают эту склонность (человек с ведущей Заботой на ключнике). Вопрос: должна ли каждая должность задевать все пять склонностей (тогда характер виден везде), или «не на своём месте — характер не проявляется» — это и есть механика? Здесь же перекос: варианты по Обычаю почти без минусов, лес копит плюсы.
