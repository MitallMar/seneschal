# Задание: сборка раздела канона

Канон «Сенешаля» перестраивается по разделам (решение автора 24.11.2026): каждый раздел — отдельный файл `kanon/NN-….md` до 25 тыс. знаков, читается одним чтением; главная версия — в ветке `lore2`; после каждого решения автора правится нужный раздел, версий больше нет. Оглавление и что каждый раздел заменяет — `kanon/README.md`. Образец готового раздела — `kanon/03-labirinty.md` и `kanon/04-labirinty-dobycha.md`, образец списка изменений — `rabota/kanon/03-04-izmeneniya.md`.

Составитель канона — не писатель текстов мира: ему можно и нужно читать `resheniya.md` (журнал решений автора) — поиском и по частям.

## Порядок

1. Прочитать устав `CLAUDE.md` (разделы «Что где», «Как читать», «Справочники: формат»), `yadro.md`, `kanon/README.md`, образец `kanon/03-labirinty.md` (форма, плотность, отсылки).
2. Прочитать источники своих разделов (таблица «Заменяет» в `kanon/README.md`) — по разделам через `python3 tools/chitat.py ФАЙЛ "раздел"`; плюс:
   - справочники `temy/` и `kraya/` по своей теме — там решения автора с [Р] и предложения с [П];
   - `resheniya.md` — найти поиском (`grep -n -i` по ключевым словам темы) все решения по своим разделам и сверить, что каждое учтено;
   - v5 разд. 9 (термины), 10 (открытые вопросы), 11 (отвергнуто), 12 (отложено) — что относится к своим разделам.
3. Собрать файлы разделов, затем список изменений `rabota/kanon/NN-izmeneniya.md` (по одному на связку разделов).
4. Самопроверка: каждый файл ≤ 25 тыс. знаков (`LC_ALL=C.UTF-8 wc -m`), оглавление читается `tools/chitat.py`, ни одно утверждение источников не потеряно (см. «Ничего не терять»).

## Правила

- **Канон — законы мира и «почему так»**, общие для мира. Местное — места, роды, города, конкретные люди, годы частных событий — не в канон: оно в справочниках `kraya/`, `temy/`; в каноне допустим пример в одну строку с отсылкой `см. kraya/x.md: Запись`.
- **Старшинство:** решение автора (`resheniya.md`, [Р] в справочниках, ядро) → канон v5 → отдельные документы → остальное. Где v5 расходится с решением — писать по решению и вносить в список изменений.
- **Ничего не придумывать.** Нет решения — не закрывать дыру самому, а оставить вопрос. Можно сводить, сокращать, убирать повторы, переформулировать яснее.
- **Ничего не терять.** Каждое утверждение источников своих разделов либо входит в файл, либо в списке изменений сказано, куда ушло: в другой раздел канона (номер), в справочник (какой), в ядро, или отброшено (почему: решение такого-то числа, отвергнуто).
- **Статусы:** всё в каноне считается решённым — помету [Р] не ставить. Предложение без решения ([предложение] v5, [П] справочников) — не в канон, а в вопросы. Где источники спорят, а автор не решил, — строка «спорят: …».
- **Вопросы** — в конце каждого файла раздел «## Открыто», в форме устава: «Вопрос N: …», 2–3 варианта, рекомендованный первым с одной строкой «почему». Сюда же — открытые пункты ядра и v5 разд. 10 по теме (на уровне закона, не местные).
- **Форма файла:** заголовок `# NN. Название`, строка «что здесь и что в соседних разделах» (с номерами соседних разделов из `kanon/README.md`), затем `## 1. …`, `### 1.1 …`. Плотно, как справочник правил: короткие абзацы и списки, без истории обсуждений. Термины — по ядру. Числа — по источнику, не по памяти.
- **Слова (решение автора 24.11.2026):** лабиринт в каноне «стригут» (не «снимают вес»), в речи людей — «обдирать», в казённых бумагах — «облегчать»; «вес» остаётся.
- **Если раздел не влезает в 25 тыс. знаков** — разделить на два файла с тем же номером и разными именами (`09-istoriya.md`, `09-derzhavy.md`) и сказать об этом в отчёте.
- Ссылки на соседние разделы — номерами (`03 §4.2`); на не собранные ещё разделы — номером из `kanon/README.md`.

## Список изменений (`rabota/kanon/NN-izmeneniya.md`)

Для автора, коротко, по каждому разделу связки:
1. Что изменилось против v5 — «было → стало, по решению такого-то числа».
2. Что добавлено из решений и документов (не было в v5).
3. Что ушло из раздела и куда.
4. Противоречия, которые не удалось развести, — с источниками.
5. Открытые вопросы — список (сами вопросы — в файлах).
6. Объём каждого файла (слова и знаки).

## Чего не делать

- Не трогать никакие файлы, кроме своих `kanon/NN-….md` и `rabota/kanon/NN-izmeneniya.md`: справочники, ядро, `kanon/README.md`, устав правит координатор после ответов автора. Если по ходу видна ошибка в справочнике — записать в список изменений, разд. «Для координатора».
- Не делать git add/commit/push. Не писать в проект claude.ai и на Google Диск.

## Отчёт координатору

Объёмы файлов; главное из списка изменений (5–10 пунктов на связку); число открытых вопросов и суть каждого одной строкой.
