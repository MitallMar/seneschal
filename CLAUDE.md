# Памятка для работы над проектом

Игра «Сенешаль»: веб, TypeScript, сборка esbuild в один HTML. Сейчас это прототип главной системы — характеров и совета: читаются ли персонажи как личности, когда совет решает дела без Сенешаля, — и хозяйства с податью, на которые совет работает. Язык игры, комментариев, документов и коммитов русский.

## Замысел и решения автора

Геймдизайн, механики и принятые решения лежат в `docs/design/` (оглавление в `docs/design/README.md`). Это главная версия: обсуждение замысла идёт в чатах проекта на claude.ai, а записывается сюда. Копии в проекте claude.ai — промежуточные: если расходятся с репозиторием, верен репозиторий.

- Задача про новую механику, баланс или интерфейс: сначала прочитай нужный документ из `docs/design/` (сейчас главный — `koncept-3.md`: ось — место и дворы, время, люди, события и следы, Сенешаль; характер и совет прототипа — `koncept-2.md`). Где документы расходятся, действует правило старшинства из `docs/design/README.md`: новее документ и позже дата решения — важнее.
- Пометки в документах замысла: **[решено]** — автор согласился, делать так; **[предложение]** и **[открыто]** — не решено, в код без задачи не нести.
- Изменил поведение игры, числа баланса по умолчанию или правила совета: обнови соответствующий документ в `docs/design/` тем же коммитом.

## Очередь задач

Задачи от автора лежат в `docs/design/backlog.md`. «Сделай следующую задачу» = первая открытая сверху в разделе «По порядку». Сделал: тем же коммитом поставь у неё `[x]`, дату по Москве, одну строку итога и перенеси в «Сделано»; тем же коммитом сверь с задачей разделы `README.md` «Что уже есть» и «Что будет дальше»: сделанное переезжает в первый, во втором остаётся только несделанное. Не получилось или нужно решение автора: не отмечай, допиши под задачей «Вопрос автору: …».

Образец правил и устройства — другая игра автора, «Тетрадь по схемотехнике» (`MitallMar/tetrad-po-skhemotekhnike`): оттуда переносятся принципы, а не код.

## Какие файлы читать под задачу

Читай только нужное: слои независимы, весь проект в контекст тянуть не надо. Типы состояния (`World`, `Person`, `Economy`, `AuthState`) и чтение из него (`holder`, `getRel`, `fitness`) — `src/sim/state.ts`; `clamp`, округления и `mean` — `src/sim/util.ts`, заново не объявлять. Как устроен код — `docs/ARCHITECTURE.md`, как проверять — `docs/TESTING.md`.

В таблице — тема, документ замысла (лежит в `docs/design/`) и главные файлы. Что читать и править подробно, какие тесты и отчёты запускать после правки и какие у темы оговорки — в `docs/ARCHITECTURE.md`, глава «Как править: по темам»: перед правкой прочитай там раздел, названный в последней колонке.

## Правила

1. После любой правки: `npm run check` (типы, линтер, тесты, сборка). Проверка в браузере разбита на разделы: после правки запускай те, что она задевает (`npm run e2e -- staff`, список: `npm run e2e -- --list`, таблица «что когда запускать» в `docs/TESTING.md`); все разделы (`npm run e2e`) — после правки общего кода (`src/sim/`, `src/ui/council/main.ts` и `app.ts`, `src/ui/dom.ts`, `index.html`, `style.css`, сборка) и когда не уверен. Полную проверку на каждый push в `main` и каждый pull request запускает GitHub (`.github/workflows/ci.yml`); красный прогон чинить до следующей задачи.
2. Законченная задача всегда попадает в `main`: ветка → pull request → дождаться зелёной проверки GitHub → слить самому, не спрашивая автора; красную проверку сначала починить. Перед push локально зелёные `npm run check` и `npm run e2e`. Исключение: документы — решения и планы в `docs/design/` и задачи в `docs/design/backlog.md` — чат проекта коммитит прямо в `main`, без pull request; код, `src/`, `test/` и `dist/` чат не трогает.
3. Сообщение коммита по-русски: что изменилось для игрока (у задач без видимых перемен — что изменилось для работы над игрой).
4. Слои: `src/ui` → `src/sim` → `src/data`, зависимости только в эту сторону. `src/sim` и `src/data` не трогают DOM и часы: они должны работать в Node, на этом держатся тесты и прогоны без экрана.
5. Числа баланса только в `src/sim/balance.ts`, каждое — ручка с диапазоном, шагом и подписью по-русски. Логика читает `BALANCE` каждый раз заново, без копий в переменные модуля: ручка должна действовать сразу. В остальном ядре остаются только шкалы (звезда 0–10, отношения −10…10) и нули с единицами.
6. Случайность только через `src/sim/rng.ts` с семенем: одно семя и одни действия игрока — одна и та же партия. `Math.random` и текущее время в `src/` не использовать.
7. Не менять ход партий незаметно. Правка, которая не должна менять поведение (экран, сборка, порядок кода), не трогает `test/parties.snapshot.json`. Правка, которая меняет его намеренно, обновляет отпечаток (`UPDATE_SNAPSHOT=1 npm test`) и говорит об этом в коммите.
8. `dist/` только собирается командой `npm run build`, руками его не править. Собранные `dist/index.html` (прототип совета) и `dist/natura.html` (эмулятор натуры) коммитятся вместе с исходниками: по ним автор играет и смотрит.
9. Не менять `id` существующих персонажей, событий, черт, меток, стремлений и должностей без причины: позже под ними будут сохранения. Новое дописывать, а не переименовывать старое.
10. Строка кода не длиннее 250 знаков без учёта русского текста (проверяет `npm run lint`); новые строки держи до 180. Тексты для игрока и комментарии пишутся одной строкой любой длины. Длинную разметку и выражения разбивай: по атрибутам тега, выноси часть в `const`.
11. Время и даты — московские (UTC+3): в сообщениях автору, в документах и в очереди задач. Серверное время (UTC) не называть. Около полуночи дата тоже берётся по Москве.
12. Одна задача — одна ветка, ветки не копятся:
    - Ветка задачи называется `iN-кратко` (`i7-chistye-vetki`); если сессия сама назначила имя ветки — работать в назначенной. В ней можно сколько угодно коммитить, проверять и править. Начинается она от свежего `main` (`git fetch origin main`), в том числе когда имя ветки то же, что у прошлой, уже слитой задачи.
    - В GitHub уходят только ветки, которые закончатся pull request. Пробы и эксперименты остаются локально.
    - После слияния: вернуться на `main`, подтянуть его и удалить локальную ветку. На GitHub слитую ветку удаляет сам GitHub (настройка «Automatically delete head branches»). Из сессии ветки на GitHub не удалять и историю не переписывать (`push --force` запрещён проверкой действий): если обычный push не проходит, слить `origin/ВЕТКА` в свою и пушить снова.
    - В начале задачи `git ls-remote --heads origin`. Если кроме `main` висят ветки уже слитых задач — не удалять, а назвать их автору списком в итоге задачи.
    - Ветки лора мира — постоянные: своя история без кода игры, ведут их чаты лора. **Главная — `lore2`** (решение автора 24.11.2026): канон по разделам — `kanon/`, справочники по краям и темам — `kraya/` и `temy/`, таблицы для игры (имена, события, зацепки) — `tablicy/`, ядро мира и отвергнутое — `yadro.md`, состав и устав — её `README.md` и `CLAUDE.md`. `lore` — прежняя картотека, заморожена и остаётся архивом. Обе не сливать, не удалять, в список висящих не включать, ничего в них не пушить. Данные для игры брать из `lore2` и только чтением (`git fetch --depth=1 origin lore2`, затем `git show FETCH_HEAD:путь`) и переносить в `src/data` обычной задачей; из `lore` — только если автор прямо попросил. Нашёл, что игра расходится с каноном `lore2`, — допиши вопрос автору; лор из сессий игры не правится.

## Доступ к GitHub из сессий Claude Code

- GraphQL недоступен, поэтому `gh pr create`, `gh pr merge`, `gh pr view` не работают. Pull request создаётся и сливается через REST:
  - создать: `gh api -X POST repos/MitallMar/seneschal/pulls -f title='…' -f head=ВЕТКА -f base=main -f body='…'`
  - слить: `gh api -X PUT repos/MitallMar/seneschal/pulls/N/merge -f merge_method=squash`
- Push ветки: `git -c push.negotiate=true push -u origin ВЕТКА`.
- Итог проверки: `gh api repos/MitallMar/seneschal/commits/SHA/check-runs` (поля `status`, `conclusion`), опрашивать раз в 30–60 секунд. Причина красной проверки — в аннотациях: `gh api repos/MitallMar/seneschal/check-runs/ID/annotations` (непройденная проверка в браузере пишет туда своё имя).
- Логи Actions через этот прокси не читаются (403): причину красной проверки воспроизводить локально теми же командами, что в `ci.yml` (`npm ci`, `npm run check`, `git status --porcelain -- dist`, `GITHUB_ACTIONS=1 npm run e2e`).
- В конце сообщения коммита и описания pull request — строки атрибуции, которые даёт сессия.
